## 一、Java 基础（15 题）

### 1. ⭐ == 和 equals 区别？
- `==`：基本类型比值，引用类型比地址
- `equals`：默认是==，String/Integer 重写后比内容
- **重写 equals 必须重写 hashCode**（HashMap 规则）

### 2. ⭐ String / StringBuilder / StringBuffer？
- String 不可变（final char[]）
- StringBuilder 可变，不安全，快
- StringBuffer 可变，安全（synchronized），慢
- **编译器优化**：`"a"+"b"` 编译期变 "ab"

### 3. ⭐ String 为什么不可变？
- final 修饰类 + final 修饰 char[]（JDK9 后 byte[]）
- 好处：线程安全、hashCode 缓存、字符串常量池

### 4. 🔥 String s = new String("abc") 创建几个对象？
- 2 个：堆中 new 的对象 + 常量池的 "abc"（如果常量池没有的话）
- 如果常量池已有 "abc"，则只创建 1 个堆对象

### 5. ⭐ 自动装箱拆箱？
- 装箱：`Integer i = 1` → `Integer.valueOf(1)`
- 拆箱：`int n = i` → `i.intValue()`
- **陷阱**：Integer 缓存 -128~127，== 比较在这个范围内为 true
- **陷阱2**：`Integer a = null; int b = a;` → NPE

### 6. ⭐ 接口和抽象类区别？
- 抽象类：单继承、有构造器、成员变量、具体方法
- 接口：多实现、无构造器、JDK8 后有 default/static 方法
- **设计角度**：抽象类是 "是什么"，接口是 "能做什么"

### 7. ⭐ 重载和重写？
- 重载（Overload）：同类、同名、参数不同、编译时确定
- 重写（Override）：子类、同名同参、运行时确定（动态分派）
- **重写不能比父类更窄的访问权限**

### 8. ⭐ Java 异常体系？
- Throwable → Error（不该 catch）+ Exception
- Exception → 受检异常（IOException）+ 运行时异常（NPE）
- **finally 不执行的唯一情况**：`System.exit(0)`

### 9. ⭐ try-catch-finally 执行顺序？
- try 有 return → 先执行 finally → 再 return
- finally 也有 return → 覆盖 try 的 return（不推荐）
- **try-with-resources**：自动关闭实现了 AutoCloseable 的资源

### 10. ⭐ 泛型擦除？
- 编译后泛型擦除为 Object（或上界）
- `List<String>` 和 `List<Integer>` 运行时都是 `List`
- **通配符**：`<? extends T>` 只读、`<? super T>` 只写（PECS 原则）

### 11. ⭐ 反射的用途和缺点？
- 用途：Spring IoC、MyBatis 映射、动态代理
- 缺点：性能差（无法 JIT）、破坏封装
- **setAccessible(true)** 可访问 private

### 12. ⭐ JDK 动态代理 vs CGLIB？
- JDK Proxy：基于接口，`Proxy.newProxyInstance`
- CGLIB：基于继承，`Enhancer`，不能代理 final 类
- **Spring**：有接口用 JDK Proxy，没接口用 CGLIB

### 13. 🔥 深拷贝和浅拷贝？
- 浅拷贝：只复制引用，`clone()` 默认
- 深拷贝：递归复制所有引用对象
- **实现**：实现 Cloneable + 重写 clone，或序列化/反序列化

### 14. ⭐ Java 中的值传递？
- Java **只有值传递**
- 基本类型：复制值
- 引用类型：复制引用地址（方法内改属性会影响原对象，但改指向不影响）

### 15. ⭐ Stream API 常用操作？
- 中间：filter、map、flatMap、sorted、distinct、limit
- 终端：forEach、collect、reduce、count、anyMatch
- **惰性求值**：中间操作不会立即执行，终端操作触发

## 二、集合框架（10 题）

### 16. ⭐ HashMap 底层原理？
- JDK1.8：数组 + 链表 + 红黑树
- 链表 >8 且数组 >64 → 转红黑树；节点 <6 退化链表
- 负载因子 0.75 → 扩容翻倍
- **hash 计算**：`(h = key.hashCode()) ^ (h >>> 16)` 扰动函数

### 17. 🔥 HashMap 扩容机制？
- 初始容量 16，扩容 ×2
- 阈值 = 容量 × 负载因子
- JDK1.8：扩容时只需判断 hash 高位 bit，0 留原位，1 移到原位+旧容量

### 18. ⭐ HashMap 为什么线程不安全？
- JDK1.7：并发扩容链表成环 → 死循环
- JDK1.8：put 并发数据覆盖（两个线程同时 put 到同一个桶）
- **解决**：ConcurrentHashMap

### 19. ⭐ ConcurrentHashMap 原理？
- JDK1.7：Segment 分段锁（16 段）
- JDK1.8：CAS + synchronized（锁链表头/红黑树根）
- **读不加锁**：volatile 修饰 Node 的 val 和 next

### 20. ⭐ ArrayList 原理？
- 动态数组，初始容量 10（首次 add 时创建）
- 扩容 1.5 倍：`oldCapacity + (oldCapacity >> 1)`
- **随机访问 O(1)，插入删除 O(n)**
- **批量插入**：`addAll` 会一次性扩容到刚好够用

### 21. ⭐ ArrayList vs LinkedList？
| | ArrayList | LinkedList |
|--|-----------|------------|
| 底层 | 数组 | 双向链表 |
| 随机访问 | O(1) | O(n) |
| 插入删除 | O(n) | O(1) |
| 内存 | 连续 | 每节点多两个指针 |

### 22. ⭐ HashSet 原理？
- 底层是 HashMap，value 是 PRESENT 常量
- 依赖 hashCode + equals 保证唯一
- **add 流程**：先 hashCode 定位桶 → equals 检查是否存在 → 不存在才插入

### 23. ⭐ TreeMap 原理？
- 底层红黑树，key 必须实现 Comparable 或传 Comparator
- 插入/删除/查询都是 O(log n)
- **自动按 key 排序**

### 24. 🔥 HashMap 的 key 用自定义对象要注意？
- 必须重写 hashCode 和 equals
- **key 不可变**：如果 key 的 hash 字段被改了，会找不到原 value
- 推荐用 String、Integer 等不可变类做 key

### 25. ⭐ fail-fast 机制？
- ArrayList 遍历中修改 → ConcurrentModificationException
- 原理：modCount 版本号，迭代器对比
- **解决**：用 Iterator.remove() 或 CopyOnWriteArrayList

## 三、多线程与并发（20 题）

### 26. ⭐ 线程的创建方式？
- 继承 Thread
- 实现 Runnable（推荐，无单继承限制）
- 实现 Callable + FutureTask（有返回值）
- 线程池 ExecutorService（生产推荐）

### 27. ⭐ run 和 start 区别？
- start：启动新线程，JVM 调用 run
- 直接调 run：在当前线程执行，没新线程

### 28. ⭐ sleep vs wait？
| | sleep | wait |
|--|-------|------|
| 类 | Thread | Object |
| 锁 | 不释放 | 释放 |
| 唤醒 | 超时自动 | notify/notifyAll |
| 位置 | 任意 | synchronized 块内 |

### 29. ⭐ 线程生命周期？
- NEW → RUNNABLE →（BLOCKED / WAITING / TIMED_WAITING）→ TERMINATED
- **BLOCKED**：等 synchronized 锁
- **WAITING**：wait/join/LockSupport.park

### 30. ⭐ synchronized 原理？
- 锁对象头中的 Mark Word
- 锁升级：无锁 → 偏向锁 → 轻量级锁（CAS自旋）→ 重量级锁（OS mutex）
- **偏向锁**：线程 ID 写入对象头，JDK15 后默认关闭

### 31. ⭐ synchronized vs ReentrantLock？
| | synchronized | ReentrantLock |
|--|-------------|---------------|
| 释放 | 自动 | 手动 unlock |
| 中断 | 不可中断 | 可中断 lockInterruptibly |
| 公平 | 非公平 | 可配置 |
| 条件 | 1 个 wait set | 多 Condition |
| 实现 | JVM 内置 | AQS |

### 32. 🔥 AQS 原理？
- AbstractQueuedSynchronizer，JUC 核心框架
- **state**（int volatile）+ **CLH 双向队列**
- 独占模式：ReentrantLock；共享模式：Semaphore/CountDownLatch
- **入队**：CAS 抢锁失败 → 包装 Node → 加入队尾 → park 阻塞

### 33. ⭐ volatile 作用？
- **可见性**：读主内存不读缓存
- **禁止指令重排**：内存屏障
- **不保证原子性**：`i++` 仍然不安全
- 底层：MESI 缓存一致性协议

### 34. 🔥 指令重排？
- 编译器重排 + CPU 重排 + 内存重排
- **经典案例**：单例双重检查锁（DCL）要加 volatile
- `new Object()` 三步：分配内存 → 初始化 → 赋引用，2 和 3 可能重排

### 35. ⭐ CAS 原理？
- Compare And Swap：比较并交换
- `Unsafe.compareAndSwapInt(obj, offset, expected, new)`
- 三个问题：ABA（AtomicStampedReference 解决）、自旋开销、只能保证一个变量

### 36. ⭐ ThreadLocal 原理？
- 每个 Thread 有 ThreadLocalMap
- key 是 ThreadLocal（弱引用），value 是值（强引用）
- **内存泄漏**：key 被 GC 后 value 仍在 → 用完必须 remove()
- **InheritableThreadLocal**：子线程可继承父线程的值

### 37. ⭐ 线程池参数？
1. corePoolSize → 核心线程数
2. maximumPoolSize → 最大线程数
3. keepAliveTime → 空闲存活时间
4. unit → 时间单位
5. workQueue → 任务队列
6. threadFactory → 线程工厂
7. handler → 拒绝策略

### 38. ⭐ 线程池执行流程？
```
提交任务 → 核心线程未满 → 创建核心线程执行
         → 核心线程满 → 入队列
         → 队列满 → 创建非核心线程
         → 最大线程满 → 执行拒绝策略
```

### 39. ⭐ 四种拒绝策略？
- AbortPolicy：抛 RejectedExecutionException（默认）
- CallerRunsPolicy：调用者线程执行
- DiscardPolicy：直接丢弃
- DiscardOldestPolicy：丢最老的任务

### 40. ⭐ 常见线程队列？
- LinkedBlockingQueue：无界（默认 Integer.MAX_VALUE），**OOM 风险**
- ArrayBlockingQueue：有界
- SynchronousQueue：不存任务，直接移交（Executors.newCachedThreadPool 用）
- **推荐用 ThreadPoolExecutor 手动创建，不用 Executors**

### 41. 🔥 死锁条件？
1. 互斥
2. 占有并等待
3. 不可剥夺
4. 循环等待
- **解决**：破坏任一条件，最常用按顺序加锁
- **排查**：jstack 查线程状态 + 找死锁链

### 42. ⭐ CountDownLatch vs CyclicBarrier？
| | CountDownLatch | CyclicBarrier |
|--|----------------|---------------|
| 计数 | 递减到 0 | 递增到 N |
| 重置 | 不可重置 | 可重置 |
| 场景 | 主线程等子任务 | 多线程互等 |

### 43. ⭐ 乐观锁 vs 悲观锁？
- 悲观锁：先加锁再操作（synchronized、SELECT FOR UPDATE）
- 乐观锁：不加锁，更新时检查版本（CAS、@Version）
- **CAS 适合读多写少，synchronized 适合写多**

### 44. 🔥 ThreadLocal 在线程池中的问题？
- 线程复用 → ThreadLocal 数据残留
- **解决**：用完 remove()，或用阿里 TransmittableThreadLocal

### 45. ⭐ ForkJoin 框架？
- 分治思想：大任务拆小任务
- 工作窃取：空闲线程从其他线程队列尾部偷任务
- **应用**：CompletableFuture、parallelStream

## 四、JVM（10 题）

### 46. ⭐ JVM 内存区域？
- **线程私有**：虚拟机栈、本地方法栈、PC 寄存器
- **线程共享**：堆、方法区（元空间）
- **堆**：新生代（Eden + S0 + S1）+ 老年代
- **元空间**：JDK8 后替代永久代，使用本地内存

### 47. ⭐ 对象创建过程？
1. 类加载检查
2. 分配内存（指针碰撞 / 空闲列表）
3. 内存初始化为零
4. 设置对象头（Mark Word + Class Pointer）
5. 执行 `<init>` 构造方法

### 48. ⭐ 对象内存布局？
- 对象头（Mark Word + Class Pointer）
- 实例数据
- 对齐填充（8 字节对齐）
- **压缩指针**：-XX:+UseCompressedOops

### 49. ⭐ GC 判断对象存活？
- 引用计数法（不用，循环引用问题）
- **可达性分析**：从 GC Roots 向下搜索
- **GC Roots**：栈中引用、静态变量、常量、JNI 引用

### 50. ⭐ 引用类型？
- 强引用：`Object o = new Object()` → 永不回收
- 软引用：内存不足时回收 → SoftReference
- 弱引用：下次 GC 必回收 → WeakReference
- 虚引用：跟踪回收过程 → PhantomReference

### 51. ⭐ GC 算法？
- 标记-清除：碎片
- 标记-整理：无碎片但慢（老年代）
- 复制：浪费空间但快（新生代）
- **分代收集**：新生代复制，老年代标记-整理

### 52. ⭐ 垃圾收集器？
| 收集器 | 区域 | 特点 |
|--------|------|------|
| Serial | 新生代 | 单线程，STW |
| ParNew | 新生代 | 多线程 |
| Parallel Scavenge | 新生代 | 吞吐量优先 |
| CMS | 老年代 | 低延迟，并发标记清除 |
| G1 | 全堆 | Region 化，可预测停顿 |
| ZGC | 全堆 | 染色指针，<10ms 停顿 |

### 53. 🔥 G1 原理？
- Region 化：堆分成 2048 个 Region
- 每个 Region 可动态是 Eden/Survivor/Old/Humongous
- **Mixed GC**：回收所有新生代 + 部分老年代
- **标记-整理 + 复制**：无碎片

### 54. ⭐ 类加载过程？
1. 加载：找 class 文件，生成 Class 对象
2. 验证：格式、元数据、字节码、符号引用
3. 准备：静态变量赋默认值（int=0）
4. 解析：符号引用 → 直接引用
5. 初始化：执行 `<clinit>` 静态代码块

### 55. ⭐ 双亲委派模型？
- BootstrapClassLoader → ExtClassLoader → AppClassLoader → 自定义
- **先委派父加载器，父加载不了再自己加载**
- **作用**：安全（防止核心类被篡改）+ 避免重复加载
- **打破场景**：Tomcat（每个 WebApp 独立 ClassLoader）、JDBC（SPI 用 ContextClassLoader）

## 五、MySQL（20 题）

### 56. ⭐ 事务 ACID？
- **A 原子性**：undo log 回滚
- **C 一致性**：业务约束
- **I 隔离性**：MVCC + 锁
- **D 持久性**：redo log 刷盘

### 57. ⭐ 事务隔离级别？
| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|------|-----------|------|
| READ UNCOMMITTED | ✓ | ✓ | ✓ |
| READ COMMITTED | ✗ | ✓ | ✓ |
| REPEATABLE READ | ✗ | ✗ | ✓(InnoDB解决) |
| SERIALIZABLE | ✗ | ✗ | ✗ |

### 58. 🔥 MVCC 原理？
- 每行记录有隐藏列：trx_id（事务ID）、roll_pointer（指向 undo log）
- **Read View**：当前活跃事务 ID 列表
- **可见性判断**：trx_id < min → 可见；trx_id > max → 不可见；在列表中 → 不可见
- **RC**：每次 SELECT 生成新 Read View → 不可重复读
- **RR**：第一次 SELECT 生成 Read View，后续复用 → 可重复读

### 59. ⭐ InnoDB 索引底层？
- **B+ 树**：非叶子只存索引，叶子存数据/主键
- 聚簇索引：数据和索引一体（InnoDB 主键索引）
- 非聚簇索引：叶子存主键，需要回表
- **为什么 B+ 树**：磁盘 IO 少、范围查询快、叶子有序链表

### 60. ⭐ 聚簇索引 vs 非聚簇索引？
- 聚簇索引：叶子节点存整行数据（InnoDB 主键）
- 非聚簇索引：叶子节点存主键值 → 需要回表
- **InnoDB 必须有主键**，没指定就用唯一非空索引，再没有就生成隐藏列

### 61. ⭐ 最左前缀原则？
- 联合索引 (a, b, c)：
  - ✅ a / (a,b) / (a,b,c)
  - ❌ b / (b,c) / c
- 范围查询右边的列失效：`a=1 AND b>2 AND c=3` → c 用不到索引

### 62. 🔥 索引失效场景？
1. 函数/计算：`WHERE YEAR(create_time)=2024`
2. 类型转换：`WHERE phone=123`（phone 是 varchar）
3. LIKE 前导模糊：`LIKE '%abc'`
4. OR 两边不全有索引
5. != / NOT IN
6. 联合索引不满足最左前缀

### 63. ⭐ EXPLAIN 关键字段？
- **type**：system > const > eq_ref > ref > range > index > ALL
- **key**：实际使用的索引
- **rows**：预估扫描行数
- **Extra**：Using index（覆盖索引）、Using filesort（需优化）、Using temporary

### 64. ⭐ 覆盖索引？
- 查询字段都在索引中 → 不用回表
- `Extra: Using index`
- **优化**：将 SELECT * 改为只查索引列

### 65. ⭐ 索引下推（ICD）？
- MySQL 5.6 引入
- 联合索引 (a,b)，`WHERE a='x' AND b LIKE '%y%'`
- 无 ICD：先回表再过滤 b
- 有 ICD：在索引层就过滤 b，减少回表次数

### 66. ⭐ 回表？
- 非聚簇索引查到主键 → 再去聚簇索引查整行数据
- **减少回表**：覆盖索引、索引下推

### 67. 🔥 MySQL 锁？
- **全局锁**：FTWRL，全库只读
- **表锁**：LOCK TABLES，开销小
- **行锁**：
  - 记录锁（Record Lock）：锁单行
  - 间隙锁（Gap Lock）：锁区间，防幻读
  - 临键锁（Next-Key Lock）：记录锁 + 间隙锁，RR 默认
- **意向锁**：表级标记，快速判断表是否有行锁

### 68. ⭐ 共享锁 vs 排他锁？
- 共享锁（S）：`SELECT ... LOCK IN SHARE MODE`，可读不可写
- 排他锁（X）：`SELECT ... FOR UPDATE`，读写都锁
- **X 锁和 S 锁互斥**

### 69. ⭐ redo log / undo log / binlog？
- **redo log**：InnoDB 引擎层，crash-safe，物理日志
- **undo log**：InnoDB 引擎层，回滚 + MVCC，逻辑日志
- **binlog**：Server 层，主从复制，逻辑日志
- **两阶段提交**：redo log prepare → binlog → redo log commit

### 70. ⭐ 主从复制原理？
1. 主库写 binlog
2. 从库 IO Thread 拉取 binlog → 写入 relay log
3. 从库 SQL Thread 读 relay log → 重放
- **三种同步方式**：全同步、半同步、异步（默认）

### 71. 🔥 慢查询优化？
1. EXPLAIN 查执行计划
2. type=ALL → 加索引
3. Using filesort → 优化排序
4. 避免 SELECT *
5. 分页优化：`WHERE id > last_id LIMIT 10` 替代 `LIMIT 100000,10`
6. 避免 JOIN 超过 3 张表
7. 子查询改 JOIN

### 72. ⭐ count(*) vs count(1) vs count(字段)？
- `count(*)`：统计所有行，**InnoDB 优化过，不取值**
- `count(1)`：统计所有行，性能和 count(*) 差不多
- `count(字段)`：不统计 NULL 值
- **count(*) 最优**（MySQL 优化器已优化）

### 73. ⭐ MySQL 大表优化？
- 分区：按时间/范围分区
- 分表：垂直拆（字段拆）、水平拆（行拆）
- 冷热分离：热数据在 MySQL，冷数据在 ES/HBase
- 读写分离：主写从读

### 74. 🔥 MySQL 调优参数？
- `innodb_buffer_pool_size`：缓冲池大小，建议物理内存 60-80%

### 77. ⭐ Spring AOP 原理？
- 面向切面编程：横切逻辑抽离
- **JDK 动态代理**：有接口时使用，`Proxy.newProxyInstance`

### 78. ⭐ Spring Bean 作用域？

### 79. ⭐ @Autowired vs @Resource？

### 82. 🔥 @Transactional 失效场景？

### 84. ⭐ Spring Boot 自动装配？

### 85. ⭐ Spring Boot 启动流程？

7. refreshContext：创建 BeanFactory → 注册 BeanDefinition → 创建 Bean

### 86. 🔥 Spring 中的设计模式？
- 工厂模式：BeanFactory / ApplicationContext

- 代理模式：AOP（JDK Proxy / CGLIB）

### 87. ⭐ @Configuration vs @Component？

## 八、Redis（12 题）

### 96. ⭐ Redis 为什么快？
1. 内存操作
2. 单线程，无上下文切换和锁竞争
3. IO 多路复用（epoll）
4. 高效数据结构（SDS、跳表、压缩列表）

### 97. ⭐ Redis 数据类型？
| 类型 | 底层 | 场景 |
|------|------|------|
| String | SDS | 缓存、计数器 |
| Hash | ziplist/hashtable | 对象存储 |
| List | quicklist | 消息队列 |
| Set | intset/hashtable | 去重、交集 |
| ZSet | ziplist/skiplist+hashtable | 排行榜 |
| Stream | radix tree | 消息流 |
| Bitmap | String | 签到 |
| HyperLogLog | String | 去重计数 |

### 98. ⭐ Redis 持久化？
- **RDB**：全量快照，fork 子进程，恢复快，可能丢数据
- **AOF**：追加日志，三种策略（always/everysec/no），数据安全
- **混合持久化**（4.0+）：RDB + AOF 增量，恢复快且数据安全

### 99. 🔥 缓存穿透/雪崩/击穿？
| 问题 | 原因 | 解决 |
|------|------|------|
| 穿透 | 查不存在的数据 | 布隆过滤器 / 缓存空值 |
| 雪崩 | 大量 key 同时过期 | 随机过期时间 / 多级缓存 |
| 击穿 | 热点 key 过期 | 分布式锁 / 逻辑过期 |

### 100. ⭐ Redis 过期策略？
- **惰性删除**：访问时检查是否过期
- **定期删除**：定期随机抽样检查
- **内存淘汰**：8 种策略
  - noeviction（默认不淘汰）
  - allkeys-lru / volatile-lru
  - allkeys-lfu / volatile-lfu
  - allkeys-random / volatile-random
  - volatile-ttl

### 101. ⭐ Redis 分布式锁？
- SETNX + EXPIRE（非原子）
- `SET key value NX EX 30`（原子）
- **问题**：锁过期但业务未完成 → 看门狗续期
- **Redisson**：可重入、看门狗、Red Lock
- **Red Lock**：向 N/2+1 个节点加锁，防单点故障

### 102. ⭐ Redis 单线程为什么效率高？
- 纯内存操作
- IO 多路复用（epoll）
- 避免线程切换和锁竞争
- **Redis 6.0 后**：IO 多线程（解析/回写），命令执行仍单线程

### 103. ⭐ Redis 主从复制？
1. 全量同步：从库连接主库 → 主库 BGSAVE → 发 RDB → 从库加载
2. 增量同步：主库写命令到 repl_baklog → 从库拉取
3. **断线重连**：PSYNC 命令，offset 断点续传

### 104. ⭐ Redis 哨兵（Sentinel）？
- 监控：检测主库是否存活
- 通知：通知运维
- **自动故障转移**：主观下线 → 客观下线 → 选举哨兵 → 选举从库 → 升主
- 选举算法：Raft

### 105. 🔥 Redis Cluster？
- 16384 个哈希槽，`CRC16(key) % 16384`
- 每个节点负责一部分槽
- **Gossip 协议**：节点间通信
- **故障检测**：PING/PONG → 标记 PFAIL → 半数标记 FAIL
- **客户端路由**：MOVED 重定向 / ASK 临时重定向

### 106. ⭐ Pipeline 和事务？
- **Pipeline**：一次性发送多条命令，减少 RTT
- **MULTI/EXEC**：事务，命令入队后原子执行
- **Watch**：乐观锁，监控 key 变化
- **Lua 脚本**：原子执行多条命令

### 107. ⭐ ZSet 跳表原理？
- 有序链表 + 多层索引
- 查找：从最高层开始，逐层缩小范围
- 时间复杂度：O(log n)
- **为什么不用红黑树**：实现简单、范围查询更方便、内存可控

## 九、计算机网络（10 题）

### 108. ⭐ OSI 七层 / TCP/IP 四层？
- OSI：物理 → 数据链路 → 网络 → 传输 → 会话 → 表示 → 应用
- TCP/IP：网络接口 → 网络（IP）→ 传输（TCP/UDP）→ 应用（HTTP）

### 109. ⭐ TCP 三次握手？
1. 客户端 → SYN → 服务端
2. 服务端 → SYN+ACK → 客户端
3. 客户端 → ACK → 服务端
- **为什么三次**：防止旧 SYN 到达服务端后建立无效连接
- **SYN 攻击**：伪造大量 SYN → 半连接队列满 → SYN Cookie 防御

### 110. ⭐ TCP 四次挥手？
1. 客户端 → FIN → 服务端
2. 服务端 → ACK → 客户端
3. 服务端 → FIN → 客户端
4. 客户端 → ACK → 服务端
- **TIME_WAIT 2MSL**：确保 ACK 到达 + 防止旧连接
- **为什么四次**：服务端收到 FIN 后可能还有数据要发

### 111. ⭐ TCP vs UDP？
| | TCP | UDP |
|--|-----|-----|
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠 | 不可靠 |
| 顺序 | 有序 | 无序 |
| 速度 | 慢 | 快 |
| 场景 | HTTP/FTP | DNS/视频/游戏 |

### 112. 🔥 HTTPS 原理？
1. 客户端发送 TLS 握手 + 随机数 + 支持的加密套件
2. 服务端返回证书 + 随机数 + 选定套件
3. 客户端验证证书 → 生成 pre-master-secret → 用公钥加密发送
4. 双方用三个随机数生成会话密钥
5. 后续用对称加密通信
- **非对称加密**：交换密钥；**对称加密**：传输数据

### 113. ⭐ HTTP 状态码？
- 200 OK / 301 永久重定向 / 302 临时重定向 / 304 Not Modified
- 400 Bad Request / 401 Unauthorized / 403 Forbidden / 404 Not Found
- 500 Internal Error / 502 Bad Gateway / 503 Service Unavailable / 504 Gateway Timeout

### 114. ⭐ GET vs POST？
- GET：参数在 URL，有长度限制，可缓存，幂等
- POST：参数在 body，无长度限制，不可缓存，非幂等
- **本质区别**：GET 是获取资源，POST 是提交数据

### 115. ⭐ Cookie vs Session vs Token？
- Cookie：客户端存储，每次请求自动带
- Session：服务端存储，通过 sessionId（Cookie）关联
- Token（JWT）：无状态，自包含，适合微服务
- **JWT 结构**：Header.Payload.Signature

### 116. ⭐ 浏览器输入 URL 到页面显示？
1. DNS 解析域名 → IP
2. TCP 三次握手
3. TLS 握手（HTTPS）
4. 发送 HTTP 请求
5. 服务器处理 → 返回响应
6. 浏览器解析 HTML → 构建 DOM 树
7. 解析 CSS → CSSOM
8. 合并 → Render Tree
9. 布局 Layout → 绘制 Paint

### 117. ⭐ DNS 解析过程？
- 浏览器缓存 → 操作系统缓存 → hosts 文件 → 本地 DNS → 根 DNS → 顶级 DNS → 权威 DNS
- **递归查询**：客户端到本地 DNS
- **迭代查询**：本地 DNS 到其他 DNS

### 121. ⭐ 虚拟内存？
